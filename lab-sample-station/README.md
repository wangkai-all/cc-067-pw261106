# 实验室样本接收台（演示）

纯前端单页应用，演示实验室样本从**接收 → 重复/冲突处理 → 分批 → 拒收/拆分/重测 → 结果补录修订 → 全程流转追溯**的完整闭环。

> ⚠️ **全部为虚构数据**（虚构人员、机构、样本编号、检测结果）。应用不连接任何真实实验室系统/LIS，不发起任何网络请求，数据只保存在浏览器 `localStorage`。

## 运行

无需构建，零运行时依赖（`jsdom` 仅测试用）：

```bash
node serve.mjs          # 然后访问 http://localhost:8080
# 或直接用浏览器打开 index.html
npm test                # 46 项领域规则 + 37 项 DOM 交互检查
```

顶栏可切换「当前经手人」，所有留痕事件记录的都是当时所选经手人。「重置演示数据」可随时回到初始虚构场景。

## 五个页面

| 页面 | 能力 |
| --- | --- |
| ① 接收/扫码/CSV | 模拟条码芯片扫码（自动带回车）、手动补录、CSV 批量导入（支持文件选择与示例载入）、今日接收记录 |
| ② 待确认 | 同编号信息冲突的左右对比队列，原始记录只读，裁决后留痕 |
| ③ 检测批次 | 新建批次、分配样本、关闭批次、录入结果、关闭后补录修订与受影响汇总提示 |
| ④ 样本档案与流转 | 全量样本搜索、父/子/合并谱系、抽屉式完整流转时间线 |
| ⑤ 总览 | KPI、按采集点统计、最近流转事件流 |

## 核心业务规则

### 1. 同编号重复到达
- 先比对**采样时间**与**检测项目**，两者完全一致才判定为重复 → **合并**，不新建档案，只在原样本上追加合并事件（含判定依据、时间、经手人）。
- 任一不一致 → 进入**待确认队列**，差异字段高亮；**原始记录绝不被覆盖**。
- 待确认裁决二选一：**维持原件**（冲突件退回）或**另建新档**（编号自动加 `-C1/-C2` 后缀），两种处理都写入双方流转链。

### 2. 交接全程留痕
接收、重复合并、冲突、分配批次、拒收、拆分、重测、结果录入、修订、批次关闭——每个事件都记录**时间戳 + 经手人 + 详情**。在任意行点「流转记录/完整流转」，抽屉时间线可沿一份样本查完整流转，父样本、拆分子件、合并件之间可互相跳转。

### 3. 批次与样本
- 批次按检测项目建立，一份多样本项目可同时进入多个批次；项目不匹配、批次已关闭时分配会被拦截。
- **拒收**必须填原因，拒收样本不可再分配/重测。
- **拆分**按检测项目分组，必须覆盖全部项目且每组非空；父样本保留并标记「已拆分」，子件编号 `-1/-2` 并回指父样本。
- **重测**不删旧结果，只登记重测事件；下次录入自动生成新版本。

### 4. 批次关闭后的补录修订
- 批次关闭后仍可补录结果，但自动生成**修订版本**（v1 → v2 → …），旧版本永久保留。
- 批次页顶部出现**修订横幅**，逐条给出修订原因，以及受影响的批次汇总（已出结果数、异常数前后对比）；批次列表显示修订次数。
- 修订同时写入批次事件与样本流转链，标记「批次已关闭后补录」。

## 建议演示动线（初始数据已铺好场景）

1. **扫码录入**：接收页点 4 枚模拟条码芯片，分别体验新样本建档（008/009）、重复合并（001）、冲突入待确认（007）。
2. **CSV 导入**：点「载入示例 CSV → 校验并导入」，一次看到新建/重复/冲突三种结果。
3. **待确认裁决**：在 ② 页对初始冲突 `S20261113-006` 做裁决，回到 ④ 页看原件未被修改。
4. **分批**：对「待分配」样本点「分配批次」，可为不同项目选不同开放批次或即时新建。
5. **拒收**：任选在途样本点「拒收」，填写原因后状态与流转链更新。
6. **拆分**：对多项目样本（如 `S20261113-001`）拆分，再把子件分别分配到对应项目批次。
7. **关闭与补测**：批次页关闭一个开放批次，再对其中样本「补录结果」，观察修订版本与受影响汇总横幅；随后到 ④ 页打开该样本看完整时间线。
8. 种子数据里 `S20261112-002`（关闭后补录）、`S20261112-004`（重测出 v2）、`S20261112-006`（重复合并）已预置好历史场景，可直接查看。
